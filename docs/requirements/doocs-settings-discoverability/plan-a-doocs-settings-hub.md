# Plan A：统一为 Doocs 设置中心

## 决策

将设置侧边栏入口统一命名为“Doocs”，使用语义明确的 `/settings/doocs` 路径；旧 `/settings/wechat` 保留重定向，避免已有链接失效。页面按能力分区，而不是只强调公众号账号。

## 交互逻辑

1. owner/admin 在“工作区设置”中看到带 Doocs 标识的“Doocs”入口；member 不显示。
2. 点击进入 `/settings/doocs`，页面标题与侧边栏名称保持一致。
3. 页面按顺序展示：
   - 编辑器状态：显示已配置/未配置、编辑器地址和连通性提示；
   - 图片上传服务：选择微信或 S3，并填写对应配置；
   - 微信公众号：账号列表、新增、编辑、删除和默认账号。
4. 未配置任何上传服务时显示明确空状态，并给出“配置微信上传”与“配置 S3”动作。
5. 保存成功后在当前区块内反馈；切换上传服务时保留已保存配置，不静默删除另一套配置。
6. 访问旧 `/settings/wechat` 时重定向到 `/settings/doocs`。

## 实现范围

- 调整 `doocsSettingsNavItem` 的名称和路径。
- 在 `App.tsx` 注册 `/settings/doocs`，并为旧路径增加兼容重定向。
- 将设置页标题、说明和空状态统一为 Doocs 语义。
- 为菜单可见性、路由兼容和三个配置分区补前端测试。
- 在实际部署环境中使用 owner、admin、member 三种角色完成浏览器验收。

## 验收标准

- owner/admin 无需猜测“微信公众号”即可从设置侧边栏找到“Doocs”。
- member 看不到入口，直接访问时也不能读取或修改配置。
- `/settings/doocs` 可直接打开，`/settings/wechat` 自动跳转且不报 404。
- 页面明确展示编辑器状态、上传服务和公众号账号三个区域。
- 微信与 S3 均未配置时有可操作的空状态。
- 刷新和窄屏滚动后入口仍可找到。
