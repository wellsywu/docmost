背景

当前添加公众号需要填写账号名称、AppID、AppSecret，并手动切换“已认证”。实际获取微信 stable_token 只依赖 AppID 与 AppSecret；账号名称只是本地展示信息，“已认证”目前也是本地布尔值，并不会向微信验证。

为什么做

  • 减少首次接入需要理解的字段。
  • 避免把用户手动开关误解成微信认证结果。
  • 在保存时验证凭据，提前暴露 AppSecret 错误和出口 IP 白名单问题。

为什么优先级低

现有 AppID/AppSecret 方式已经可用，并且即使以后增加扫码授权，它仍需要作为高级备用方式保留。本项主要改善交互和错误反馈，不阻塞当前 Doocs 集成。

验收标准

  • 新增账号时只有 AppID 和 AppSecret 为必填项，账号名称可在验证成功后自动生成或另行修改
  • 移除用户手动控制的“已认证”开关，并区分“凭据有效”与微信官方认证类型
  • 保存前由服务端验证微信凭据，错误时明确区分凭据无效、网络失败和出口 IP 不在白名单
  • 验证成功后 AppSecret 加密入库，列表、编辑和错误响应均不回显明文
  • 已有账号无需迁移即可继续使用，并支持主动重新验证

不在本条范围内

  • 微信开放平台扫码授权
  • 模拟登录微信公众号后台或保存浏览器 Cookie
  • 公众号草稿和正式发布 API
