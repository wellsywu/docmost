背景与原因

“扫码绑定公众号”不是普通公众号 AppID/AppSecret 提供的能力，而是微信开放平台第三方平台授权。部署方必须先申请并审核通过第三方平台，同时提供公网 HTTPS 的授权事件接收地址和授权回调地址。

授权过程中，平台使用 component_verify_ticket、component_access_token 和 pre_auth_code 生成微信官方授权页。管理员扫码确认后，微信回调一次性授权码，再换取 authorizer_refresh_token。该流程不会把公众号自身 AppSecret 交给 Docmost。

微信官方参考：获取第三方平台接口调用凭据、获取预授权码、获取授权账号信息。

为什么优先级低

  • 现有 AppID/AppSecret 手动接入已经可用。
  • 需要外部平台申请、微信审核、公网回调、事件验签、权限申请和长期令牌运维，不是单纯增加二维码组件。
  • 并非每个自托管部署都拥有第三方平台资质，因此不能作为唯一接入方式。
  • 当前账号凭据主要用于微信图片上传；完整草稿和发布 API 仍是独立范围。

验收标准

  • 只有配置并验活微信开放平台第三方平台后才显示可用的“扫码授权公众号”入口；未配置时展示明确前置条件
  • 授权请求绑定当前工作区和发起管理员，回调校验 state、有效期和一次性使用，不能跨工作区绑定账号
  • 扫码成功后自动获取公众号名称、类型、授权权限和授权状态，无需录入公众号 AppSecret
  • authorizer refresh token 加密入库，访问令牌按需刷新，任何前端接口和日志均不泄露令牌
  • 二维码过期、拒绝授权、权限不足、取消授权和回调失败均有明确状态与恢复路径
  • 微信图片上传服务同时支持手动凭据和开放平台授权凭据，手动 AppID/AppSecret 入口继续作为备用方式
  • 部署文档列出第三方平台审核、公网 HTTPS 回调、事件验签、IP 白名单和权限集要求

不在本条范围内

  • 替部署方申请或保证通过微信开放平台审核
  • 模拟登录公众号后台、保存 Cookie 或使用非官方扫码登录
  • 完整的公众号草稿、群发和正式发布 API
